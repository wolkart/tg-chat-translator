# Design

## Context

Сейчас бот запускается только руками из клона репозитория: `npm start`, `.env` по
`.env.example`. Что для установки уже есть в коде:
- `main.ts` читает `.env` из текущей папки, а базу — из `data/translator.db` относительно
  неё (`env.ts`). Значит, папку бота задаёт рабочая папка процесса, и коду не нужно знать,
  где он стоит;
- при старте `getMe`: любой отказ — «Telegram не принял токен» и `exit(1)`, даже если это
  просто нет сети;
- grammY при `getUpdates` с ответом 401 или 409 перестаёт опрашивать и выбрасывает ошибку
  (`handlePollingError`), и процесс падает. 409 приходит, когда тот же бот опрашивает
  Telegram из другого места;
- `/start` от владельца открывает панель, сообщения не от владельца бот не обрабатывает;
- база — обычный режим журнала SQLite, без WAL.

Образец — `news-reposter`: `install.sh` (Docker, `/dev/tty` для вопросов в `curl | bash`,
sudo, установка Docker через `get.docker.com`) и `uninstall.sh` (поиск по метке Compose,
копия базы до вопроса, подтверждение словом).

Что проверено до спеки 2026-10-16:
- `nodejs.org/dist/latest-v24.x/SHASUMS256.txt` содержит сборки `darwin-arm64`,
  `darwin-x64`, `win-x64.zip` и `win-arm64.zip`, сейчас v24.22.0;
- Node 24 поддерживает macOS от 13.5 и Windows от 10 (`BUILDING.md` ветки v24.x);
- `codeload.github.com/wolkart/tg-chat-translator/tar.gz/refs/heads/main` отдаёт архив
  без авторизации.

## Goals / Non-Goals

**Goals:**
- три пути — одна логика вопросов: что спросить и как проверить, написано один раз и
  покрыто тестами;
- скрипты оболочки делают только то, что без Node не сделать;
- шаги установщика — реестр: платная версия добавит шаг (например, ключ лицензии) новой
  строкой, не правя скрипты;
- на компьютере — ни прав администратора, ни изменений вне папки бота, кроме записи
  автозапуска.

**Non-Goals:**
- нет своего способа следить за ботом на компьютере (статус, кнопка «перезапустить»):
  перезапуск — та же команда установки;
- нет обрезки журнала `data/bot.log` — пишется мало, см. «Риски»;
- нет подписи скриптов и своего домена для команды установки.

## Decisions

### 1. Скрипты оболочки тонкие, вопросы — на TypeScript

Все скрипты (`install.sh`, `install.ps1`) делают одно и то же:
1. проверка системы;
2. Node на месте;
3. код на месте и `npm ci`;
4. **`node src/install/setup.ts --env <путь к .env>`** — вопросы;
5. автозапуск;
6. ожидание старта.

Шаг 4 общий для всех путей: проверка связи, токен, поиск владельца, запись `.env`.

Альтернатива — вопросы в bash и PowerShell отдельно. Отвергнута:
- логика пишется дважды и расходится;
- тестов на `node:test` к ней не написать;
- JSON ответов Telegram в bash без `jq` не разобрать, а на голом Ubuntu `jq` нет.

`setup.ts` — реестр шагов `{ id, run(ctx) }`, которые идут по порядку:
`connectivity → token → owner → write-env`. В `ctx`:
- ввод-вывод: `say`, `ask`, `askMasked`;
- `fetch`;
- собранные ответы.

Тесты подменяют ввод-вывод и `fetch`. Если `.env` уже содержит `BOT_TOKEN` и `OWNER_ID`,
шаги вопросов пропускаются. Важна проверка значений, а не наличия файла: на сервере
пустой `.env` создаётся заранее (решение 7).

Коды выхода `setup.ts`: 0 — `.env` готов, 1 — человек не прошёл шаг или нет связи. Текст
причины `setup.ts` печатает сам, скрипт оболочки просто останавливается.

В `curl | bash` вход скрипта занят самим скриптом, поэтому `setup.ts` запускается с
`< /dev/tty`, как вопросы в news-reposter.

### 2. Своя копия Node, всегда

На Mac и Windows установщик всегда ставит Node 24 в `<папка бота>/node/`, даже если в
системе есть подходящий. Порядок:
1. берёт имя архива для системы и процессора из `SHASUMS256.txt` ветки `latest-v24.x`;
2. скачивает архив;
3. сверяет SHA-256: `shasum -a 256` на Mac, `Get-FileHash` на Windows;
4. распаковывает: `tar` на Mac, встроенный `tar.exe` на Windows (Expand-Archive — запасной
   путь, он в разы медленнее на 30 МБ мелких файлов).

При обновлении Node скачивается заново, только если `node/…/node --version` не начинается
с `v24.`.

Почему не системный Node: Homebrew обновит его до 26 или удалит, и бот молча перестанет
работать. Своя копия — 50 МБ на диске и одна и та же версия у всех. Права администратора
не нужны: всё лежит в папке пользователя. Код и Node скачиваются `curl` (на Mac) и
`Invoke-WebRequest` (на Windows). Поэтому у файлов нет отметки «скачано из интернета», и
Gatekeeper не спрашивает разрешения на запуск `node`.

### 3. Код — архивом, папка бота одна на все пути

Содержимое папки бота (`~/tg-chat-translator`, на Windows — `%USERPROFILE%\tg-chat-translator`):

```
.env            токен и владелец — остаётся при обновлении
data/           база и журнал — остаётся
node/           своя копия Node (Mac, Windows) — остаётся
src/ package.json …   код — заменяется целиком
```

Обновление на компьютере:
1. архив распаковывается во временную папку рядом;
2. там же выполняется `npm ci --omit=dev`;
3. только если оба шага прошли, из папки бота удаляется всё, кроме `.env`, `data/` и
   `node/`, а новое переносится на место. Удалённые в новой версии файлы так не остаются;
4. бот перезапускается.

Сломалась загрузка или `npm ci` — старый код работает дальше. Рабочая папка процесса — папка
бота, поэтому `main.ts` находит `.env` и `data/` без правок.

Три переменные для проверки до слияния:
- `BRANCH` — ветка, по умолчанию `main`:
  `curl …/feat/one-line-install/install.sh | BRANCH=feat/one-line-install bash`;
- `DIR` — папка бота;
- `ARCHIVE` — путь к локальному архиву (`git archive`) вместо GitHub. Так установщик
  прогоняется во временной папке без пуша.

### 4. Владелец — по /start, без подтверждения апдейтов

Шаг `owner` опрашивает `getUpdates` раз в 2 секунды до 3 минут:
- **без `offset`** — ни одно сообщение не подтверждается, и бот после запуска получит тот
  же `/start` и ответит панелью. Подтверждение сожгло бы его, а вместе с ним
  `business_connection`, если владелец уже подключил бота к аккаунту;
- **без `allowed_updates`** — этот параметр Telegram запоминает до следующего вызова,
  установщик со своим списком отрезал бы боту апдейты из лички до первого опроса;
- **короткий опрос, не long polling** — с неподтверждёнными апдейтами long polling
  возвращается сразу, и цикл крутился бы впустую.

Ищется последний `message` из личного чата с текстом `/start`. Ответ «нет» добавляет его
`from.id` в отвергнутые, ожидание продолжается. Те, кто писал боту до владельца, получат от
запущенного бота тишину: чат с ботом — только для владельца.

Отказы `getUpdates`:
- 409 «terminated by other getUpdates» — бот запущен в другом месте, установка
  останавливается (спека);
- 409 из-за вебхука — `deleteWebhook` без `drop_pending_updates`, и опрос повторяется: grammY
  всё равно снял бы вебхук при старте.

### 5. Токен вводится звёздочками

`askMasked` переводит ввод в «сырой» режим (`setRawMode`) и на каждый знак печатает `*`. Так
человек видит, что вставка сработала, а токен не попадает в запись экрана для рилса. Без
терминала (вход не TTY) — обычный ввод без звёздочек. Проверка — `getMe`: 401 значит
«не принял токен», сетевая ошибка — «нет связи» с подсказкой про VPN, без повтора вопроса.

### 6. Остановка без выхода: бот «засыпает», а не падает

Бот завершает процесс с ошибкой только тогда, когда перезапуск поможет. В двух случаях
перезапуск бесполезен:
- 409 при опросе — тот же бот работает в другом месте;
- 401 — токен отозван.

Тогда бот перестаёт опрашивать Telegram, пишет причину и **остаётся жить без работы**.
При 409 он перед этим пишет владельцу, где остановился. Место называется по системе:
«на Mac (<имя компьютера>)», «на Windows (<имя компьютера>)», «на сервере». В контейнере
имя хоста — случайный id, поэтому для Linux имени нет.

Почему не выход с кодом 0. Все три надзирателя тогда пришлось бы учить различать коды:
- у launchd это `KeepAlive.SuccessfulExit`;
- Docker с `unless-stopped` перезапускает при любом коде;
- политика `on-failure` после перезагрузки сервера не поднимет контейнер, который
  перезагрузка убила.

С «засыпанием» правило у надзирателей одно — **процесс кончился → поднять через 10
секунд**. Уснувший бот занимает около 50 МБ памяти. Проснуться ему помогает только
перезапуск, то есть команда установки или перезагрузка, и об этом говорит сообщение.

Кто из двух копий уснёт: Telegram отдаёт 409 той копии, чей опрос перебили, то есть
прежней. Новая установка работает, старая сообщает о себе.

Нет сети при старте (`getMe` не дошёл) — повтор внутри процесса с паузой 5 → 10 → 30 → 60
секунд и одной строкой в журнал. Сейчас в этом случае пишется неверное «не принял токен».
Решение по ошибке — функция `classifyStop(error)` (`sleep-conflict`, `sleep-token`,
`retry`, `crash`), её покрывают тесты на образцах ошибок grammY.

### 7. Сервер: Docker, вопросы — в одноразовом контейнере

На Linux `install.sh` ведёт себя как в news-reposter:
- sudo, если запущен не от root;
- ставит недостающие `curl` и Docker через `get.docker.com`;
- код скачивает тем же архивом, что на Mac, в `~/tg-chat-translator`.

Дальше:
1. `docker pull node:24-slim` — отдельно, чтобы отказ Docker Hub узнать по этому шагу, а
   не по выводу сборки;
2. `docker compose build`;
3. пустой `.env` с правами `600` — без него Compose не запустит даже одноразовый
   контейнер;
4. `docker compose run --rm --no-deps --user root -v "$DIR:/out" translator node
   src/install/setup.ts --env /out/.env < /dev/tty`;
5. `docker compose up -d`.

Почему вопросы в контейнере, а не Node на хосте: Node на сервере уже есть внутри образа, и
второй Node ради одной минуты вопросов не нужен. `--user root` — потому что образ работает
под `node`, а папка на хосте принадлежит root.

Compose — `restart: unless-stopped`, база — в именованном томе `translator-data`, как в
news-reposter. Удаление ищет контейнеры, тома и сети по метке проекта.

### 8. Автозапуск на Mac — LaunchAgent

Файл задания — `~/Library/LaunchAgents/com.github.wolkart.tg-chat-translator.plist`:
- `RunAtLoad` и `KeepAlive: true`, `ThrottleInterval: 10`;
- `WorkingDirectory` — папка бота;
- программа — `node/bin/node src/main.ts`;
- вывод — в `data/bot.log`.

Включается `launchctl bootstrap gui/$(id -u)`, обновление перезапускает задание
`launchctl kickstart -k`, удаление — `launchctl bootout`. Прав администратора не нужно.
macOS при этом покажет уведомление «Добавлены фоновые объекты» с именем `node` — УСТАНОВКА
это называет.

Отвергнуто — `nohup` и запуск из `.zshrc`: бот не переживёт перезагрузку или поднимется
только при открытом Терминале.

### 9. Автозапуск на Windows — запись «Run» и скрытый надзиратель

В `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` пишется значение
`tg-chat-translator`: `powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden
-File "<папка>\run.ps1"`. Скрипт `run.ps1` лежит в репозитории. Он запускает `node.exe
src\main.ts` с выводом в `data\bot.log` и после выхода поднимает его через 10 секунд, по
кругу. Установщик запускает его так же сразу, не дожидаясь входа в систему. Перед
запуском, при обновлении и при удалении установщик останавливает прежний надзиратель и
`node.exe`: их находят по пути к папке бота в командной строке процесса
(`Win32_Process`).

Почему не Планировщик заданий:
- задание «при входе в систему» без прав администратора создаётся ненадёжно —
  `schtasks /SC ONLOGON` требует их;
- его «перезапуск при сбое» не срабатывает на код выхода программы.

Надзиратель всё равно понадобился бы, а запись «Run» не требует прав администратора и видна
человеку в «Параметры → Приложения → Автозагрузка».

`node.exe` — консольная программа, и без скрытого PowerShell висело бы окно, закрытие
которого убивает бота. Скрытый запуск при входе на долю секунды мелькает окном — это
приемлемо.

Строка TLS 1.2 стоит в начале команды установки для Windows
(`[Net.ServicePointManager]::SecurityProtocol='Tls12'; irm … | iex`). Без неё старый
PowerShell 5.1 на Windows 10 может не открыть соединение с GitHub ещё до того, как
скрипт получит управление.

### 10. Удаление: копия базы — `VACUUM INTO`

Копию снимает `node src/install/backup.ts <файл>`: SQLite `VACUUM INTO` даёт целую копию,
даже пока бот работает. Отдельный `sqlite3` не нужен, на Windows его нет. На компьютере
используется своя копия Node, на сервере — `docker compose exec`, затем
`docker compose cp`. Снимается до вопроса, как в news-reposter: человек решает, уже зная,
сохранились ли настройки. При отказе копия удаляется. Папка бота удаляется, только если в
ней лежат `src/main.ts` и `package.json` с именем `tg-chat-translator`: `rm -rf` по
переменной — место, где ошибка стоит дороже всего.

### 11. Замер моделей — ключ из базы

`scripts/eval-injection.ts` берёт ключи так же, как бот: из `.env` и из базы панели.
Прогон — 3 раза по набору на каждой из четырёх моделей панели. Таблица в README — простым
языком:
- цена 1000 переводов;
- сколько попыток подмены модель перевела честно;
- обычные сообщения без ошибок;
- скорость ответа.

Сырые ответы остаются в `data/eval/`.

## Risks / Trade-offs

- [Антивирус примет скрытый PowerShell в автозагрузке за вредоноса — это частый приём
  вредоносов] → живая проверка с Защитником Windows. Если ругается — запасные варианты по
  очереди: `conhost.exe --headless`, затем свёрнутое окно в панели задач. УСТАНОВКА
  называет предупреждение и что нажать.
- [`irm | iex` блокирует антивирус или политика компании] → в УСТАНОВКЕ — текст ошибки и
  совет поставить на сервер.
- [raw.githubusercontent.com и nodejs.org из России открываются через раз] → текст про
  VPN у каждого скачивания; сервер за рубежом снимает вопрос.
- [Кириллица и пробелы в имени папки пользователя Windows] → все пути в кавычках; живая
  проверка на пользователе с кириллическим именем, если найдётся такая машина.
- [Mac или ноутбук уснул — переводы опаздывают] → Telegram держит апдейты сутки, после
  пробуждения бот догоняет. README честно говорит «на компьютере — попробовать, на сервере —
  работать».
- [Журнал `data/bot.log` растёт без обрезки] → бот пишет только старт, сбои и оповещения,
  это килобайты в день; обрезка — когда появится повод.
- [Ставится всегда `main`: неудачный пуш сразу уходит покупателям] → в `main` сливается
  только проверенное живьём, это уже правило автора. Выпуски с тегами — после MVP.
- [Уснувший бот не просыпается сам, когда лишнюю копию удалили] → сообщение владельцу
  говорит, что делать. Самопроверка «раз в час» отвергнута: она перебивала бы рабочую
  копию и устраивала пинг-понг.
- [PowerShell-скрипты не проверить на Mac: `pwsh` здесь нет] → синтаксис и поведение
  проверяются на живой Windows-машине. Без неё Windows-путь не считается готовым.

## Migration Plan

Существующих установок, кроме тестовой у автора, нет. Тестовый бот автора продолжает
запускаться `npm start` из клона: рабочая папка, `.env` и `data/` — те же. Проверка до
слияния идёт с ветки (`BRANCH=…`), поэтому ветку надо запушить в публичный репозиторий —
по команде автора.
