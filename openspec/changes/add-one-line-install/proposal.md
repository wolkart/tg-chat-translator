# Proposal

## Why

Переводчик уже переводит личку, пишет первым и настраивается кнопками, но поставить его
может только автор: нужен Node, клон репозитория и `.env` руками. MVP — «поставил одной
строкой и настроил кнопками»: рилс показывает путь от команды в терминале до первого
перевода, а YouTube — оба пути, компьютер и сервер. Это последний шаг до MVP.

Пути три, потому что у покупателей разные машины:
- **сервер** — главный путь: бот работает круглосуточно. Docker и `install.sh`, как в
  news-reposter;
- **Mac** и **Windows** — попробовать за пять минут, без Docker. Docker Desktop на
  компьютере отброшен 2026-10-08: на Mac его первый запуск делается руками, на Windows
  нужен WSL2 и иногда BIOS, это 2+ ГБ, а Docker Hub с 2024-05-30 закрыт для РФ. Стек
  ничего не компилирует (`.ts` без сборки, одна зависимость, встроенный SQLite), поэтому
  хватает своей копии Node. Windows — у большинства покупателей, поэтому он в MVP
  (решение автора 2026-10-16), даже если первая версия выйдет шероховатой.

## What Changes

- **Одна команда на систему.** Mac и сервер — `curl -fsSL …/install.sh | bash`: скрипт
  сам выбирает путь по системе (Mac — без Docker, Linux — Docker). Windows —
  `irm …/install.ps1 | iex` в PowerShell.
- **На компьютере — без Docker и без прав администратора.** Установщик кладёт свою копию
  Node 24 в папку бота и сверяет её контрольную сумму с nodejs.org. Чужие версии Node он
  не трогает. Код скачивается архивом с GitHub, git не нужен: на чистом Mac вызов git
  предлагает поставить инструменты разработчика Apple. Старая система (macOS ниже 13.5,
  Windows ниже 10) — понятный отказ с советом поставить на сервер.
- **Установщик спрашивает только токен бота.** Токен он сразу проверяет у Telegram и
  называет бота по имени. Владельца находит сам: «Напишите своему боту /start» — и
  спрашивает «Это вы: Артём (@wolkart)?». Если за 3 минуты никто не написал, просит
  ввести id вручную. Тот же `/start` бот обрабатывает первым после запуска, поэтому
  панель открывается сама. Ключ модели установщик не спрашивает: он вставляется кнопкой
  в боте.
- **Проверка связи.** Telegram недоступен — установка останавливается с текстом «похоже,
  нужен VPN на весь компьютер». OpenRouter недоступен — предупреждение, установка идёт
  дальше. Docker Hub недоступен на сервере — отказ с советом взять сервер за рубежом.
- **Автозапуск.** На Mac бот стартует при входе в систему и поднимается после сбоя
  (launchd). На Windows так же, без прав администратора и без окна консоли. На сервере —
  перезапуск Docker.
- **Повторный запуск команды — обновление.** Код скачивается заново, `.env` и база
  остаются на месте, вопросов нет, бот перезапускается.
- **Бот в двух местах.** Если тот же бот запущен ещё где-то (сначала на компьютере, потом
  на сервере), прежняя копия останавливается и пишет владельцу, где удалить лишнюю.
  Отозванный токен тоже останавливает бота без перезапуска по кругу. Сеть пропала —
  бот поднимается сам, когда она вернётся.
- **Удаление одной командой** (`uninstall.sh`, `uninstall.ps1`). Скрипт снимает
  автозапуск и удаляет папку бота, но сначала сохраняет копию базы и предупреждает, что в
  ней ключ. Подтверждение — словом «удалить».
- **Документация.** README для покупателя: сервер как главный путь, таблица «что видите /
  в чём дело», раздел «Как модели справляются» — свежий замер четырёх моделей панели
  простым языком. УСТАНОВКА до каждого клика: BotFather, сервер, Mac, Windows,
  подключение бота к аккаунту, ключ в панели, первый перевод, удаление.
- **Замер моделей.** Скрипт замера берёт ключ из базы, как бот, и прогоняется на Claude
  Haiku 5.5, GPT-5.6 Luna, Gemini 3.1 Flash Lite и DeepSeek V4 Flash.

**Вне рамок:**
- Linux-компьютер без Docker — на Linux один путь, Docker;
- выбор версии при установке и выпуски с тегами — ставится всегда последняя `main`;
- переезд настроек с компьютера на сервер: после удаления ключ и языки вставляются
  заново, это минута;
- смена бота или владельца без переустановки;
- запрет Mac засыпать и обход сна — бот работает, пока компьютер не спит, об этом
  говорит УСТАНОВКА;
- совет включить «Restrict bot usage» в BotFather — нужна отдельная живая проверка
  (`BACKLOG.md`);
- режим через бота и группы — после MVP.

## Capabilities

### New Capabilities

- `installation`: как бот попадает на машину и живёт там:
  - одна команда на систему и выбор пути;
  - своя копия Node и проверка системы;
  - вопросы установщика: токен и владелец по `/start`;
  - проверка связи;
  - автозапуск и когда бот поднимается сам, а когда нет;
  - обновление повторной командой;
  - один бот — одна установка;
  - удаление.

### Modified Capabilities

Нет: переводы, панель и оповещения работают как раньше. Новое сообщение владельцу о
втором запуске описано в `installation`.

## Impact

- Новые файлы в корне репозитория:
  - `install.sh`, `uninstall.sh` — Mac и Linux;
  - `install.ps1`, `uninstall.ps1` — Windows;
  - `Dockerfile`, `docker-compose.yml`, `.dockerignore`;
  - `README.md`, `УСТАНОВКА.md`.
- Новый модуль `src/install/` — общая для трёх путей часть установщика на TypeScript:
  проверка связи, токен, поиск владельца, запись `.env`. Её запускает каждый скрипт
  после того, как Node на месте.
- `src/main.ts` — коды выхода для автозапуска и сообщение «бот запущен в другом месте»
  перед остановкой.
- `scripts/eval-injection.ts` — ключ из базы.
- Внешние адреса установщика — только постоянные: `api.telegram.org`, `openrouter.ai`,
  `nodejs.org`, `github.com` / `codeload.github.com`, на сервере ещё `get.docker.com` и
  Docker Hub. Адресов от человека установщик не принимает.
- Зависимостей не добавляется. Тесты — на `node:test`, сеть подменяется; скрипты
  оболочки проверяются живьём на чистом пользователе macOS, Windows-машине и сервере.
- Отступление от домашнего стандарта — путь на компьютер без Docker — записывается в
  `CLAUDE.md` продукта.
