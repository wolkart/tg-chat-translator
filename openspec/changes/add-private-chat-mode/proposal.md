# Proposal

## Why

Механику режима лички проверили вручную 2026-10-08: бот видит личку владельца, а сообщение,
отправленное от его имени, у собеседника выглядит обычным. Кода пока нет. Первый шаг —
тонкий сквозной кусок: человек пишет владельцу на своём языке, владелец читает перевод и
отвечает по-русски, а собеседник получает ответ на своём языке. Этот кусок проверяет весь
путь целиком, годится для первого рилса и задаёт ядро, на которое лягут остальные режимы.

## What Changes

- Бот, подключённый к аккаунту владельца, получает сообщения из его личных чатов. Сначала
  он проверяет право отвечать от имени владельца; если права нет, пишет владельцу, что
  включить.
- Для каждого собеседника, который пишет не на языке владельца, в чате владельца с ботом
  появляется своя тема. В ней — перевод каждого сообщения, а под ним свёрнутый оригинал.
- Чаты на языке владельца бот пропускает: ничего не хранит и ничего не отдаёт модели.
  Язык определяется на месте, по алфавиту, без сети.
- Перевод делает языковая модель. Она видит последние реплики разговора, держит «ты/вы»
  и сленг, язык оригинала определяет сама. Провайдер берётся из таблицы, как в
  news-reposter. Пара языков — дефолт первого запуска (русский ↔ английский), хранится
  в базе; языки в коде — данные, а не ветки.
- Владелец отвечает в теме на своём языке — бот переводит и отправляет собеседнику от
  его имени. Ответ, написанный вне темы, находит адресата по цепочке: тема → ответ на
  сообщение → единственный активный разговор → кнопки «Кому?».
- Фото, голосовые, стикеры и прочие вложения собеседника приходят в тему без перевода,
  подпись к ним переводится. Вложение владельца из темы уходит собеседнику так же.
- Сообщения, которые владелец написал прямо в личке, повторяются в теме — разговор там
  полный.
- Любая поломка уходит владельцу в чат с ботом человеческим текстом, без ключей и
  токенов. Если не удался перевод входящего, владелец видит оригинал с пометкой. Если
  не ушёл ответ, видит причину и готовый перевод.
- Повторная доставка апдейта после перезапуска не создаёт дублей и не шлёт собеседнику
  второе сообщение.
- Каркас проекта: TypeScript на Node 24 без сборки, `node:sqlite`, grammy, тесты на
  `node:test` на сохранённых образцах апдейтов, холостой прогон `--dry`.

**Вне рамок этого изменения:** правило суток и кнопки «Скопировать» / «Отправить через
бота» (шаг 2), режим через бота (шаг 3), группа (шаг 4), панель настроек и полная
самопроверка BotFather (шаг 5), Docker, `install.sh`, README и УСТАНОВКА (шаг 6),
перевод голосовых (платная версия), правки и удаления сообщений собеседником.

## Capabilities

### New Capabilities

- `private-chat-relay`: режим лички — подключение бота к аккаунту владельца и проверка
  прав, приём сообщений из личных чатов, отправка ответа владельца собеседнику от его
  имени, вложения, повтор собственных сообщений владельца, защита от дублей.
- `owner-topics`: сторона владельца, общая для всех режимов, — одна тема на собеседника
  в чате с ботом, оформление перевода с оригиналом, восстановление удалённой темы и
  маршрутизация ответа владельца.
- `translation`: перевод моделью с контекстом разговора, таблица провайдеров, пара
  языков владельца, изоляция текста собеседника от инструкций модели, окно истории.
- `language-detection`: локальная проверка «написано на языке владельца или нет»,
  которая решает, заводить ли разговор.
- `owner-alerts`: сообщения владельцу о поломках — без секретов и без потока
  одинаковых сообщений.

### Modified Capabilities

Нет: спек в проекте ещё нет.

## Impact

- **Код:** с нуля — `package.json`, `tsconfig.json`, `src/` (ядро-конвейер, режим лички,
  темы, перевод, определение языка, хранилище, оповещения), `test/` с образцами апдейтов.
- **Зависимости в проде:** одна — `grammy`. В разработке — `typescript` и `@types/node`.
- **Настройки:** `.env` — `BOT_TOKEN`, `OWNER_ID`, ключ провайдера модели, `DB_PATH`.
  Появится `.env.example`. Переменные `TEST_*` нужны только для одноразовых проверок.
- **Данные:** файл SQLite в `data/` (уже в `.gitignore`). В нём разговоры, темы и окно
  последних реплик. Чаты на языке владельца в базу не попадают.
- **Внешние системы:** Telegram Bot API (long polling, Business Mode, темы в личке) и API
  провайдера модели. Других адресов бот не открывает.
- **Публичный репозиторий:** образцы апдейтов в `test/` обезличиваются: ни настоящих id,
  ни имён, ни текстов переписки.
